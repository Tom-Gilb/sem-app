## How Kai's Claude uses this document

1. **Read the sem-app repo's `CLAUDE-FOR-KAI-ZEN.md` bootstrap file first** — it names this Portfolio and the recommended session order.
2. **Open this file second** when porting.  Read the Catalog.
3. For each pattern you plan to port, follow the file paths listed to the SEM App implementation.
4. Read the JSDoc header of each named file — it contains the port pattern with worked examples.
5. If the entry has an "Adoption checklist," follow it.  If not, the JSDoc + Port shape column together are enough.
6. Adopt the pattern in Kai-Zen (or Graphmetrix) with the app-specific naming from the "Namespacing" column.
7. If adoption differs from the SEM App implementation, APPEND (never overwrite) a row in the "Twin adaptations" appendix at the bottom.
8. Loop 3-7 for every pattern needed.  The Portfolio is a menu, not a mandate — port only what Kai-Zen or Graphmetrix needs.

## Standing update rule (SUPREME)

**Every SEM App ship that touches a portable pattern MUST update this Portfolio in the same commit as the code change.**  Not next week.  Not "eventually."  In the same commit.

Recognition triggers for "this ship touches a portable pattern":
- Modifying any file listed in the Catalog rows above
- Adding a new architectural pattern that could apply to Kai-Zen or Graphmetrix
- Refactoring a store, composable, or export path
- Extracting a shared component or composable
- Adding a new SUPREME rule with cross-app applicability
- Renaming or moving any file referenced in the Catalog (update the row before moving)
- Deleting any file referenced in the Catalog (remove or replace the row; do NOT leave a dead link)

If any of these apply → add / update the Portfolio row → then commit.

**Mechanical enforcement:**
- Pre-Ship Rule-Walk Row 19 asks the question every ship.
- Feature-Smoke invariant `portfolio-links-not-broken` trips before ship if any file path is missing.
- CLAUDE.md SUPREME rule "Twin-Portability-Portfolio-Update" fires the recognition triggers.
