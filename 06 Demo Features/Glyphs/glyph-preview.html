Colour system v7 — 8 types · Function=Green · Resource=Dark Green · Task=→O→* · 2026-05-16 (Tom Gilb + Kai Gilb + Claudian)

Violet #7c3aed — Value. Royal · worth · benefit. Kai: "royal, let's make him happy."
Green #16a34a — Function. Good to go · capability active. Kai: "good to go."
Orange #ea580c — Solution. Creative means. Warm; not danger-red, not royal-violet.
Red #dc2626 — Constraint. Danger · hard limit · must-not-exceed. Universal stop signal.
Dark amber #ca8a04 — Evo Step. Process · time · increment. White text contrast ~4.3:1 (WCAG AA). Bright yellow #facc15 as glyph dot accent.
Slate #374151 — Task. Neutral work. Deliberately "boring" — no semantic colour load. Keyed: →O→* (effort in · process · sub-level output · not Level of Concern).
Blue #2563eb — Stakeholder. Person · authority · trust — and inanimate entities (data, laws, systems). Keyed: ←¶→ (bilateral exchange: value ← identity ¶ resources →). People-centric blue.
Dark Green #166534 — Resource. Money · budget · input cost. Kai: "green for money." Keyed: →O (left half of →O→).

Red and green are used freely for status signals (good / bad, pass / fail) — they are not avoided. Tom confirmed: "red/green ARE useful signals." Colour rationale v6 (2026-05-16): Value=Violet ("royal" — Kai), Function=Green #16a34a ("good to go" — Kai), Resource=Dark Green #166534 ("green for money" — Kai). All three are Kai's original suggestions, all honoured in v6. Two greens are kept distinct by luminance: bright #16a34a (43% lightness) = "go, active"; dark #166534 (25% lightness) = "money, cost." What is avoided is using only red vs green to distinguish two spec-type icons pairwise. Semantic distinctions in composite glyphs (Function, Value, Constraint) are carried by stroke weight and dash pattern first; colour is additive on top. v7 (2026-05-16): Task keyed icon changed from [v] to →O→*. →O→* is compositionally precise and slots into the functional grammar family (→O→=Function, →O=Resource, [→O→]=Constraint, →O→*=Task). [v] was a checkbox pun; →O→* is a grammar.

Mono grammar (works in any single colour — black, white, or otherwise): DASHED stroke = resource / cost (consumed, entering the system). SOLID stroke = value output (produced, leaving the system). BOLD stroke weight = constraint bracket (hard outer bound). MEDIUM stroke weight = solution bracket (acceptable constraint — context, not primary subject). FILLED DOT = data point / value level instance (the * symbol made geometric). LEFT CHEVRON < = past / already-delivered anchor. HALF FUNCTION (→O, no right arrow) = Resource — cost goes in, nothing comes out of this entry. ASTERISK (*) AT OUTPUT TIP = Task — output is sub-level, inside the system, not at the Level of Concern. Contrast with ✳ in Value (= confirmed measurement at Level of Concern). →O→* = same functional grammar as →O→ (Function) but terminated with * rather than value delivery.

Stakeholder
mono
colour
←¶→
·

←¶→ · Solid ← = value TO the stakeholder (they receive; solid = value grammar). Centre ¶ = identity: a paragraph of documented interests; ALSO a left-facing human profile — bowl=head, stems=body, eye dot=face looking left at the arriving value. Double meaning: typographic AND figurative, simultaneous. Dashed → = resources FROM the stakeholder (dashed = resource/cost grammar). Tri-colour: violet=value · blue=identity · green=resources. Brown (cited in Tom Gilb, Stakeholder Engineering, Dec 2024): "Follow the resources — every entity that provides resources, whether internal or external, labor or facilities, and equipment, is a stakeholder." The → is not just descriptive — it is the diagnostic arrow: trace any dashed resource flow back to its source and you have found a stakeholder. Tom's ←¶→ independently converged on Brown's principle. Not just people: data, laws (GDPR), systems, line managers allocating team time — each a resource provider, each a stakeholder. Blue = trust, authority, people-centric.

Free source: Tom Gilb, Stakeholder Engineering (Dec 2024) — ResearchGate (open access)
