1.11Implied Entries Panel — Advanced Parsing Tier 1 (rule-based domain inference)
💡 N implied · + accept · ✕ dismiss

add screenshot

Tom 2026-05-17: "How is it going with my request earlier today for advanced parsing?" After the stage-1 classifier creates chips, an inline Implied Entries Panel appears below the three chip sections proposing ADDITIONAL entries inferred by domain knowledge — zero LLM cost (Tier 1: rule-based only). Architecture: computeImpliedEntries(chips) in impliedHierarchies.ts — pure function, 16 rules, each with triggers: {group, pattern: RegExp}[] and suggest: ImpliedSuggestion[]. A rule fires if ANY trigger matches ANY chip. Deduplicated by (group, lowercase-text) key; chips already present are filtered out. 16 seeded rules: AI/ML means → accuracy/performance/latency values; engineer/customer/patient/student/doctor → domain-specific implied peer stakeholders; revenue/budget/profit → finance values; security/auth means → security values; database/server/infra → uptime/availability/reliability; family/child/parent → related family stakeholders; data stakeholders → privacy/compliance; efficiency/speed → productivity values; quality/defect → reliability/satisfaction. UI: violet/indigo gradient header "💡 Suggested additions (N implied by your input)" · three sub-sections (👤 Who / 📊 How Well / ⚙ How) · each chip is group-colored (indigo/emerald/orange matching parent sections) with a colored + badge · :title="sug.why" tooltip shows the rule rationale on hover · accepting a suggestion pushes to the parsed array and that chip disappears immediately from the panel (reactive, no extra state) · dismiss button (item-level ✕) hides the panel · panel auto-hides when all suggestions exhausted (v-if="total > 0") · re-parse re-shows dismissed suggestions (stage watcher resets _showImplied = true). UI Rules compliance: inline panel (not a surface) — no registerExclusiveSurface, no CloseDot (item ✕ not window close), no ScrollContainer (naturally short), no select-none on body. Twin-portable: the rule table in impliedHierarchies.ts is a pure data structure with no Vue dependency — trivially portable to any runtime as the Tier 1 inference engine.Planguage Analysis2026-05-17Tom + Claudian
