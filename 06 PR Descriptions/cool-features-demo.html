Three glyph families — semantically orthogonal (Tom 2026-06-04):
1. Color Glyphs identify a Planguage ENTRY TYPE (Function / Value / Solution / Constraint / Resource / Stakeholder / Evo-Step / Task).
2. Keyed Action Glyphs identify an ACTION performed on a spec (Copy [*]=[*] · Email [*]→@ · Save *→[*] · Get [*]→* · Edit [*]→[**]). They render in currentColor so they inherit context (button text colour).
3. Nav Tab Glyphs identify a VIEW / WORKSPACE.
Never use a Keyed Action Glyph for an entry type. Never use a Color Glyph for an action. THIS IS OK (Tom verbatim).

▶ Analyze-Spec Compound Glyphs — [TYPE]→? — 7 PROPOSED (2026-06-05)

The pattern [*]→? means "analyze a spec entry" — a spec item inside brackets, a transformation arrow, and a question mark (insight/analysis result). The * can be replaced with the specific type icon. These are compound glyphs — the outer [ ] brackets (slate) act as the entry-type container; the inner mini icon identifies WHICH type is being analyzed; the cyan → is the transformation (analysis happening); the violet ? is the result (insight, question answered).
Resources compound installed in Stage 10 Pin 2. Others are PROPOSALS — awaiting Tom's approval before shipping as .vue components.

Keyed Form Preview (canonical colours) Meaning Status
[*]→? Analyze any spec entry (generic). Use when the entry type is unknown or mixed. * = any Planguage entry. PROPOSAL — base pattern
[→O]→? Analyze Resource entries. "Query the Resource budget: what is being spent, on what, and is it optimal?" Inner →O = Resource icon (dashed arrows in, oval = system boundary, no output arrow — resource consumed). Canonical dark green = Kai "green for money". ✅ INSTALLED — Stage 10 Pin 2
[→O→]→? Analyze Function entries. "Is this function present? Is it delivering value? Are resources adequate?" Inner →O→ = full Function icon (orange dashed resource arrows in, blue oval capability, cyan solid value arrows out). PROPOSAL
[O--*→]→? Analyze Value entries. "Are Goals being reached? What is the current Status vs Tolerable?" Inner O--*→ = Value icon (blue source-Function circle, cyan scale axis, data-instance dot, delivery arrow). PROPOSAL
[←§→]→? Analyze Stakeholder entries. "Are stakeholder interests accounted for? Who is missing? Are value + resource flows to/from this stakeholder correct?" Inner ←§→ = Stakeholder icon (violet value IN arrow, blue hand-drawn §, green dashed resource OUT arrow). PROPOSAL
[→O→*]→? Analyze Task entries. "Are tasks properly scoped? Do they trace to an Evo Step? Are effort estimates realistic?" Inner →O→* = Task icon (dashed effort in, circle task process, solid output arrow, dim asterisk for sub-level output). PROPOSAL
[<→+→]→? Analyze Evo Step entries. "Is this step delivering its committed Value Goal? Are the Resources on budget? Has it been measured (Stage 8)?" Inner <→+→ = Evo Step icon (amber chevron = past anchor, yellow dots = value delivered, plus = accumulation). PROPOSAL

Special cases — entry types whose notation already contains brackets:
Constraint [→O→] — the Constraint icon's own bold orange brackets ARE the [*] container. The compound "Analyze Constraint" is simply: full Constraint icon + →? appended. No extra outer brackets needed (that would produce confusing [[→O→]]→?).
Solution [*]→ — similarly, the Solution icon's medium orange brackets serve as the container. Compound: full Solution icon + →? appended = [*]→→? (the first arrow belongs to the Solution, the second → is the transformation). Visually reads as "query the solution path."
